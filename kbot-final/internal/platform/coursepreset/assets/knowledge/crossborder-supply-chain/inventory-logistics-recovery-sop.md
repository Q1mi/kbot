# 跨境库存与物流异常恢复 SOP

| 字段 | 内容 |
| --- | --- |
| 文档编号 | CB-SC-001 |
| 版本 | 2026.08 |
| 适用范围 | 跨仓库存、物流超时和订单异常协同 |
| 责任角色 | 供应链运营、仓储、物流、客服审批人 |

## 1. 事件分级

- P1：已超过 `ship_by`，且没有任何满足 SLA 的库存与物流组合；
- P2：原仓缺货或原渠道失效，仍存在可执行替代方案；
- P3：库存与物流均可履约，需要进行成本或时效优化。

等级用于安排处理优先级，不能绕过状态校验、资金审批或库存审批。

## 2. 恢复流程

1. 查询订单，确认市场、SKU、数量、状态、原仓和时效承诺；
2. 查询所有相关仓库，仅使用 `available` 计算可调拨量；
3. 查询目标市场的候选物流，保留 `sla_eligible=true` 的渠道；
4. 建立“仓库 × 渠道”候选矩阵，列出库存、时效、费用和约束；
5. 按可履约性、时效风险、成本和操作复杂度排序；
6. 涉及调拨或退款时生成独立审批事项；
7. 执行后重新读取业务状态，确认动作已经生效。

## 3. 调拨规则

创建库存调拨必须同时满足：

- 数量为正整数；
- 源仓与目标仓不同；
- 源仓 `available >= transfer_quantity`；
- SKU 与订单商品一致；
- 调拨后仍有满足订单 SLA 的履约路径；
- 使用稳定幂等键；
- 审批记录包含源仓、目标仓、数量、订单和业务原因。

推荐幂等键：`transfer:{order_id}:{sku}:{from}:{to}:{quantity}`。

源仓可用量不足、仓库相同或订单状态发生变化时，业务系统应拒绝调拨。收到拒绝响应后，更新事实并重新规划，禁止直接重复提交新幂等键。

## 4. 物流选择

候选物流需同时考虑：

- 是否满足 SLA；
- 预计运输天数；
- 运费和币种；
- 发货仓、目的市场和渠道适用性；
- 订单承诺时间剩余量。

课程基准数据中，4PX US Priority 为 `12.80 USD / 7 天`，UPS Ground 为 `9.40 USD / 4 天`，两者均满足 SLA。实际选择仍须结合履约仓与当前订单时间窗。

## 5. 恢复失败与升级

以下情况升级给供应链负责人：

- 多个系统返回的库存不一致；
- 已超过发货承诺；
- 没有满足 SLA 的物流渠道；
- 调拨会影响更高优先级订单；
- 订单已部分发货，需要拆单处置；
- 写操作审批被拒绝或执行结果未知。

## 6. 审计字段

每次恢复记录事件等级、订单和 SKU、原始事实、候选矩阵、选择依据、工具调用、幂等键、审批人、执行结果、复核时间和后续责任人。
