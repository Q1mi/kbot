# 理赔材料审核与赔付审批 SOP

| 字段 | 内容 |
| --- | --- |
| 文档编号 | IN-CL-002 |
| 版本 | 2026.08 |
| 适用范围 | 车险碰撞案件的材料核验、补件与赔付审批 |
| 控制级别 | 补件通知和赔付批准均需人工审批 |

## 1. 案件状态

- `assessing`：案件正在审核，可执行责任评估、风险分流、补件或赔付审批；
- `collecting_documents`：等待补充材料，收到材料后重新进入事实核验；
- `suspected_fraud`：已进入疑似欺诈流程，停止常规自动赔付；
- `approved`：赔付已批准，禁止重复批准；
- `rejected`：案件已拒绝，后续复议由人工流程处理。

## 2. 标准材料

碰撞险课程案例的完整材料包括：

- `accident_report`：事故报告；
- `damage_photo`：车辆损失照片；
- `repair_invoice`：维修发票。

材料存在并不直接代表内容真实有效。审核结果应区分“已提交”“格式有效”“内容一致”“已核验”四个层次。

## 3. 审核流程

1. 读取案件，核对状态、保单号、事故时间、索赔金额和材料；
2. 读取保单，核验有效状态、保险期间、产品版本、限额和免赔额；
3. 使用责任评估工具获取 `eligible`、理由码和 `max_payable`；
4. 检查材料完整性与关键字段一致性；
5. 使用风险特征工具完成支付前分流；
6. 缺件时准备最小、明确的补件清单；
7. 条件全部满足时准备赔付审批，金额不超过确定性上限。

## 4. 补件规范

补件请求应包含缺失材料名称、用途、格式要求、提交渠道和截止时间。推荐幂等键：

`documents:{claim_id}:{sorted_missing_document_types}`

已存在相同补件任务时复用原任务，避免向客户重复发送通知。

## 5. 赔付批准门槛

赔付批准需同时满足：

- 案件状态为 `assessing`；
- 责任评估 `eligible=true`；
- 关键材料完整且一致；
- 风险分低于 `0.70`；
- 批准金额不超过 `max_payable`；
- 审批人已确认金额、理由和收款信息；
- 使用稳定幂等键。

推荐幂等键：`approve:{claim_id}:{approved_amount_minor}:{currency}`。

## 6. 课程基准案例

`CLM-2026-0001` 当前状态为 `assessing`，材料包含事故报告、损失照片和维修发票，索赔金额 `6,800 CNY`，最高可赔金额 `6,300 CNY`，风险分 `0.08`。该案例可以进入赔付审批准备，实际批准仍需人工确认。

## 7. 异常与转人工

- 材料字段冲突或疑似篡改；
- 风险分达到 `0.70`；
- 事故时间处于保险期间临界点；
- 保单、责任或金额工具结果冲突；
- 案件状态在审批前发生变化；
- API 返回重复处理、业务冲突或未知结果。

## 8. 审计记录

记录案件事实、保单与产品版本、材料清单、责任理由码、金额算式、风险分与规则集、补件或批准参数、审批人、幂等键和执行结果。
