# 跨境订单取消、退款与数据边界规范

| 字段 | 内容 |
| --- | --- |
| 文档编号 | CB-PO-002 |
| 版本 | 2026.08 |
| 适用范围 | 商品运营 Agent 的取消退款建议与数据使用 |
| 控制级别 | 涉及资金的写操作必须经过人工审批 |

## 1. 退款资格

课程业务系统仅允许对 `awaiting_shipment` 订单发起退款。执行前必须核验：

1. 订单存在且状态仍为 `awaiting_shipment`；
2. 取消窗口 `cancellation_open=true`；
3. 退款币种与订单币种一致；
4. `0 < refund_amount <= order_amount`；
5. 当前订单未存在语义相同的已完成退款；
6. 已取得业务人员对金额和原因的明确确认。

`partially_shipped` 案件需要区分已发货与未发货商品，由人工售后人员确认可退范围。`cancelled` 订单进入重复退款检查，不再直接生成新的退款动作。

## 2. 幂等键规范

每次退款使用稳定、可追踪的幂等键。推荐格式：

`refund:{order_id}:{reason_code}:{amount_minor}:{currency}`

同一业务意图重试时复用原幂等键。退款金额、币种或原因发生实质变化时，创建新的审批记录并使用新的幂等键。

## 3. 原因码与说明

退款说明至少包含：

- 原因码，例如 `OUT_OF_STOCK`、`SLA_UNRECOVERABLE`、`BUYER_CANCELLATION`；
- 订单状态和取消窗口；
- 已尝试的履约恢复方案；
- 退款金额、币种及计算依据；
- 事实来源和查询时间。

禁止在原因说明中加入未经工具或人工材料证实的归责结论。

## 4. 商品运营数据边界

### 可直接使用

- 订单状态、金额、市场和履约明细；
- 仓库可用量、预留量；
- 物流费用、预计天数、SLA 资格；
- 当前工具返回的操作 ID 和审批状态。

### 需要额外数据源

- 广告消耗、自然流量、点击率和转化率；
- 商品毛利、促销预算和平台佣金明细；
- 竞品销量、竞品价格和市场份额；
- 买家画像、复购概率和生命周期价值。

缺少额外数据源时，可以提出待验证假设，并明确标注数据需求。不得用推测值代替业务事实。

## 5. 审批与异常处理

退款工具调用前，界面应展示订单号、金额、币种、原因、幂等键和风险提示。审批通过后才执行写操作。

出现以下情况时停止自动动作：

- 状态在查询后发生变化；
- 金额超出订单实付金额；
- 币种不一致；
- 幂等结果显示已处理；
- 退款与物流、仓储事实相互冲突；
- API 返回业务冲突或未知状态。

## 6. 输出模板

建议输出依次包括：事实摘要、退款资格、已评估恢复方案、建议金额、审批事项、风险与待补信息。执行完成后补充退款操作 ID 与最终状态。
